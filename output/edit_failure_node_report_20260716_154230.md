# 编辑链路错误节点追踪报告

**报告时间**：2026-07-16 15:42:30（Asia/Shanghai）  
**数据范围**：最近一轮 `EDG_001` 至 `EDG_010` 编辑链路及编辑覆盖审核结果  
**追踪原则**：优先以事件流中的 `TASK_FAILED`、`TASK_COMPLETED`、产物下载结果和审核结果判断；同一编辑 case 的多轮可能复用同一个 `task_id/session_id`。

## 一、结论摘要

本轮错误不能统一归因于 Agent 内容生成。主要分为以下几类：

1. `EDG_005_T02`：内容中台返回 HTTP 409，属于上游任务状态/冲突错误。
2. `EDG_007_T02`、`EDG_009_T03`：SSE 连接中断，但 history 恢复成功；其中 `EDG_009_T03` 最终审核通过，说明 SSE 断开不等于任务失败。
3. 多个轮次：接口返回完成，但本地未形成可供审核读取的长图；其中 `EDG_009_T01/T02` 的事件流实际已返回 `index.html/index.png`，属于本地下载/落盘链路未接上，不是上游没有产物。
4. `EDG_010_T01`：超过本地 30 分钟无完成事件，按超时失败处理。
5. `EDG_002`、`EDG_008`：引用的原始患者故事没有可用前置任务标识，编辑链路在前置检查阶段失败，未调用编辑 Agent。

## 三、失败归属

| 分类 | 归属节点 | 是否属于内容修改错误 |
|---|---|---|
| HTTP 409 | 内容中台 SSE/任务状态 | 否，上游接口失败 |
| SSE 断开后 history 恢复 | 任务传输层 | 否，需看 history 和最终产物 |
| 最终长图缺失 | 产物获取/下载/落盘 | 否，当前无法审核 |
| 审核输入不足 | 审核证据准备 | 否，需人工补充证据 |
| 30 分钟无终态 | 本地任务监控 | 否，无法确认 Agent 内容结果 |
| 原始故事前置失败 | 生成链路前置 | 否，编辑未开始 |

因此，本轮不能把所有失败轮次统计为“Agent 修改不满足需求”。只有在最终长图已经成功获取、覆盖审核实际执行，并且审核结果明确指出 `evaluation_focus` 未满足时，才应归类为内容修改问题。

## 四、开发排查建议

1. 编辑任务完成判定同时校验 `TASK_COMPLETED`、文件列表和最终长图下载结果。
2. SSE 断开后继续轮询 history，直到确认终态和产物完整，不能仅凭连接异常直接失败。
3. 对 `artifact_missing` 单独记录，不要写成审核 `skipped` 或内容审核失败。
4. 对 HTTP 409 记录中台原始响应，并增加任务状态检查和有限重试。
5. 覆盖审核输入不足时输出 `evidence_insufficient`，与 `content_not_satisfied` 分开统计。
6. 每个错误节点的结果文件必须保留 `occurred_at`、`node`、`error_type`、`raw_error`、`task_id`、`session_id` 和本地处理结果。
